# TAB — Telegram Agents Bridge

Ранее Agent Hub. Текущая разработческая поставка — portable `target/release/TAB.exe`.
Идентификатор приложения, ключи настроек и `%LOCALAPPDATA%\AgentHub` сохранены для совместимости с существующей базой и секретами. Формат `.agent-hub-theme.zip` также сохранён.

Локальный Windows-мост между установленными CLI-агентами и личным Telegram-чатом. Rust/Tokio Core, SQLite, Tauri 2, React/TypeScript и Fluent UI 9.

**Первая сборка MVP 0.1.0, ещё не завершённая приёмка.** Проверенные механизмы и открытые пункты перечислены в [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). Исследование и целевая архитектура: [AGENT_HUB_PLAN.md](AGENT_HUB_PLAN.md).

## Запуск

После сборки приложение находится в `target/release/agent-hub.exe`, per-user установщик — в `target/release/bundle/nsis/Agent Hub_0.1.0_x64-setup.exe`. Эта разработческая поставка не подписана Authenticode. Установка и WebView2 работают от текущего пользователя.

1. **Агенты → Найти агенты.** CLI должны быть установлены и авторизованы вами заранее. Включите нужные. Для Claude/OMP требуется локально принять отсутствие подтверждённой OS sandbox.
2. **Настройки.** При необходимости выберите тему и автозапуск. Добавлять проекты или разрешённые папки в Hub не нужно.
3. **Telegram.** Укажите bot token из BotFather и собственный **числовой User ID**. Username / `@username` не подходит: свой ID можно получить у [@userinfobot](https://t.me/userinfobot), нажав Start. Сохраните настройки и нажмите «Подключить». TAB покажет на ПК случайный шестизначный PIN.
4. **На телефоне:** `/start`, затем отправьте боту PIN с экрана TAB. Код появляется только после нажатия Connect на ПК, а не при автоподключении или запуске приложения. Он действует 5 минут и принимается один раз; после подтверждения исчезает. Если срок истёк, снова нажмите Connect. После подтверждения выберите сессию и агента, затем отправьте задачу. Проект и нужные папки обсуждаются с агентом. Другие poller/webhook этого бота должны быть остановлены.
5. Закрытие окна скрывает его в трей. «Остановить всё» отменяет задачи; «Выйти» в трее завершает Core. Автозапуск приложения включается отдельно в настройках. Настроенный бот автоматически подключается при запуске Hub без приветствия в личку; временные сетевые ошибки повторяются автоматически. Явное «Отключить» сохраняется до следующего «Подключить». Полный выход завершает соединение, но не выключает автоподключение. PIN-доступ после перезапуска открывается заново.

Desktop содержит только **Агенты / Telegram / Настройки**. Сессии, задачи и файлы управляются через Telegram. Локальные подтверждения появляются отдельными карточками при поступлении native request.

В настройках выбирается акцентный цвет. Фон — только матрица; её анимацию можно отключить. Карточки и боковая панель пропускают фон и размывают его. Иконки Codex и Claude Code взяты из Lobe Icons, OMP — из его upstream-репозитория; происхождение и лицензии указаны в `third_party/NOTICES.md`.

Интерфейс использует полупрозрачные стеклянные панели над локальным ASCII-фоном, светлую/тёмную темы и акцент `#FECA17`. Верхняя панель и кнопки — штатные Windows; тема и цвет заголовка согласованы с интерфейсом через DWM (старые версии Windows используют native light/dark fallback). Закрытие по-прежнему скрывает окно в трей. Анимация матрицы отключается в настройках, при скрытой странице приостанавливается и учитывает системный reduced motion. Прозрачность относится к фону внутри приложения; рабочий стол за окном не захватывается.

Под сообщениями агента доступны «Остановить задачу» и «Закончить сессию». TAB не ведёт собственный список диалогов и не сохраняет переписку. Контекст текущего соединения с CLI существует в памяти; после завершения задачи её текст удаляется из буферов после доставки, после завершения сеанса удаляется его контекст. Кнопка старого сеанса не завершает другой текущий сеанс. Ответы поддерживают Markdown (жирный, курсив, зачёркивание, ссылки, списки и заголовки); код и блоки кода отображаются моноширинно. Длинные ответы отправляются несколькими сообщениями, без отдельного журнала TAB. Историю в самом Telegram и нативную историю CLI приложение не удаляет.

Новые сессии запускаются в служебной папке `%LOCALAPPDATA%\AgentHub\workspaces\<provider>`, отдельно от базы и секретов Hub. Native sandbox и approvals сохраняются: обсуждение пути в чате само по себе не выдаёт доступ. Возможность доступа вне рабочей папки зависит от CLI и поддерживаемых native запросов. Существующие сессии сохраняют прежнюю рабочую папку. Служебные workspace-записи в базе нужны для транспорта и вложений; это не пользовательский каталог проектов. Это изменение UX заменяет обязательный выбор проекта из исходного архитектурного плана.

## Telegram

| Команда | Действие |
|---|---|
| `/start`, `/sessions` | Выбрать или создать сессию |
| `/pcs`, `/status` | Состояние единственного ПК |
| `/stop` | Отменить задачи выбранной сессии |
| `/lock` | Закрыть доступ и остановить remote-задачи |
| `/files` | Предложить файлы из `.agent-hub/outbox` для явной отправки |
| `/answer ID JSON` | Ответить конкретному native question; формат зависит от агента |
| `/help` | Краткая справка |

Approvals — отдельные кнопки с одноразовым ID. Ответ «да» в обычном чате не разрешает действие. Codex questions ожидают JSON вида `{"question_id":{"answers":["ответ"]}}`, Claude — `{"текст вопроса":"ответ"}`. В OMP native dialogs подтверждаются локально. Неизвестные permission requests требуют остановки задачи.

Прикреплённые файлы накапливаются в наборе, закреплённом за сессией: нажмите «Отправить вложения». Для сохранения оригинала отправляйте изображение как document. Голос пока передаётся файлом без транскрипции. Вложения появляются в `.agent-hub/inbox` под случайными именами. Hub не изменяет `.gitignore` проекта.

Чтобы получить результат, попросите агента записать его в `.agent-hub/outbox`, вызовите `/files` и выберите файл. Hub сверяет SHA-256 и разрешённый путь перед отправкой. Файл вне outbox не экспортируется. Файлы проектов и вложений не являются архивом переписки и остаются на диске.

## Разработка

```powershell
# Из корня репозитория
npm.cmd --prefix apps/desktop ci
.\scripts\dev.ps1
.\scripts\dev.ps1 -Build
.\scripts\verify.ps1
```

Требуются Node.js, Rust MSVC, Visual Studio Build Tools и WebView2. В этой рабочей папке установлен локальный Rust в `.tools`; scripts используют его без изменения системного PATH. `.tools`, `target`, `node_modules` и `dist` не входят в Git. `Cargo.lock` и `package-lock.json` фиксируют зависимости.

`hub-core` содержит domain, storage worker, process supervisor, adapters, access control и Telegram. `apps/desktop/src-tauri` — тонкий desktop host. `fake-cli` — только executable для integration fixtures, он не включается в desktop installer.

## ASCII-темы и Theme Generator

В «Настройки → Фон» доступны «Матрица» и «Saveli». Десять отдельных нажатий Tab подряд
открывают Developer Settings: там доступны секретная тема «pr0n» и выбор розовой
иконки трея `*` / `:3`. Другие клавиши сбрасывают счётчик; удерживание Tab не засчитывается.
Developer Settings скрыты после перезапуска; секретный фон сбрасывается на матрицу,
выбранная иконка трея сохраняется. Это скрытый интерфейс, не защита файлов темы.
Настройки цветов и скорости
взяты из предоставленных архивов. Следующая тема загружается до плавного перехода;
выбор сохраняется локально. MP4 в приложение не включается.

Отдельный редактор: `tools/theme-generator/index.html`. В установщике он находится
в папке `theme-generator` рядом с exe; открывается в Edge/Chrome без сервера и Python.
Поддерживает локальную загрузку ролика, настройку и экспорт `.agent-hub-theme.zip`.
Автоматического импорта ZIP через интерфейс Agent Hub пока нет.

При изменении редактора выполните `python tools/theme-generator/build_player.py`,
чтобы обновить используемый приложением проигрыватель. Перед импортом встроенных
тем `import_theme.py` проверяет размер распакованных данных и SHA-256.

## Данные и восстановление

Данные находятся в `%LOCALAPPDATA%\AgentHub`; bot token — в Windows Credential Manager. Одноразовый PIN, его pepper и хеш живут только в памяти до ввода, истечения срока или отключения; PIN не сохраняется в Telegram inbox, event log или аудите. Старый постоянный PIN больше не используется. Лимит попыток сохраняется в SQLite и не сбрасывается при выдаче нового кода или перезапуске. После перезапуска grants недействительны, pending approvals устаревают, незавершённые задачи не переотправляются. Неопределённая отправка Telegram остаётся `unknown`.

Схема SQLite v2 сохраняет только настройки и технические данные безопасности/дедупликации. Сеансы, задачи, события, интерактивные запросы, буферы ответов и очередь доставки используют TEMP-таблицы с `temp_store=MEMORY`. После выхода они исчезают; недоставленные сообщения не восстанавливаются. При переходе с v1 удаляются старые таблицы переписки и сгенерированные TAB файлы `exports/<UUID>.jsonl`, выполняется очистка свободных страниц SQLite. Это не удаляет историю самих CLI, сообщения Telegram или файлы проектов.

Job Object управляет жизненным циклом принадлежащих Hub процессов; это не файловая или сетевая песочница. Доверенными остаются локальная Windows-сессия и выбранные CLI. Telegram cloud chat не обеспечивает E2EE.
